# Bundle format

A bundle is a directory describing one agent. The required and recommended
layout for v0.1:

```
my-agent/
├── genome.yaml            # required
├── agent.lock.yaml        # required (or agent.lock)
├── behavior.contract.yaml # required
├── runtime/               # optional, generated by `bundle compile-runtime`
│   ├── plain.compiled
│   ├── langgraph.compiled
│   └── crewai.compiled
├── prompts/               # required (at least one file)
│   └── system.md
├── tools/                 # optional
├── memory/                # optional
├── policies/              # optional (*.rego enforced; see "Policies")
├── knowledge/             # optional
├── runtime/               # optional, generated by `agenomic compile`
│   ├── plain.compiled/
│   ├── langgraph.compiled/
│   ├── crewai.compiled/
│   ├── docker.compiled/
│   └── wasm.compiled/
└── .agenomicignore       # optional, gitignore-style
```

## Runtime adapters (`runtime/*.compiled/`)

`agenomic compile` lowers `genome.yaml` into runnable source for one or more
frameworks under `runtime/<target>.compiled/` — the `genome → runtime` step of
the format, analogous to how an OCI image is built from a Dockerfile. Targets:
`plain` (FastAPI + provider SDK), `langgraph`, `crewai`, `docker` (the `plain`
service as a pinned OCI image), and `wasm` (a `componentize-py` WASI component
with prompts inlined). `docker` and `wasm` produce deployable artifacts run by
their own hosts (`docker run`, a WASI runtime) rather than by `agenomic run`,
whose launcher handles `command` entrypoints only.

Each compiled tree embeds its prompts and a `manifest.json` listing every
generated file's BLAKE3 plus the source genome hash. Output is deterministic, so
two compiles of the same genome are byte-identical and the manifest can be
folded into a release attestation. These trees are *generated* — regenerate with
`agenomic compile` rather than hand-editing.

## Policies (`policies/*.rego`)

`policies/` may contain OPA/Rego files. They are evaluated by `agenomic policy
eval` and as a fail-closed gate inside `agenomic run` (before the agent is
spawned). A policy declares `package agenomic` with a boolean `allow` rule
(defaults to `false`) and an optional `deny[reason]` set; the launch is
permitted only when `allow == true` and `deny` is empty. Non-`.rego` files in
`policies/` (e.g. human-readable `.md`) are ignored by the engine.

## Always excluded

`.git/`, `target/`, `node_modules/`, `__pycache__/`, `dist/`, `.agenomic/`,
plus credential files: `.env`, `.env.*`, `*.pem`, `*.key`, `id_rsa`,
`id_ed25519`, `*.p12`, `*.pfx`. Use `--allow-symlinks` to permit symlinks
(off by default).

## Archive

`agenomic build` packs the bundle as a tar archive (mtime=0, mode 0644 for
regular files, deterministic header) and zstd-compresses it. Output filename
extension: `.bundle.tar.zst`.

The archive header order matches the manifest order — that is, files are
appended to tar in lexicographic POSIX-path order.

## Runtime artifacts

`agenomic bundle compile-runtime <DIR>` compiles the declarative bundle into
adapter-specific launch plans under `runtime/`. The generated files are
deterministic and portable: they capture the chosen adapter, the resolved
execution contract (declared or derived), prompt bindings, policy/tool/knowledge
locks, and any warnings that still require human completion.
